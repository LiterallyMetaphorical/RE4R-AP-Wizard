BioRand fork binary provenance
==============================
This records what the launcher's assets/BioRand/ payload was built from.
The payload itself is a build artifact (git-ignored); rebuild it with:

  cd biorand-re4r-ap
  dotnet publish src/biorand-re4r/biorand-re4r.csproj -c Release -r win-x64 --self-contained true -o <out>
  copy <out>/* into RE4R-AP-Launcher/assets/BioRand/

DOOR LOCKS ARE BANNED IN AP MODE - DO NOT "FIX" THIS
    LockDoor/LockShutter CREATE a lock component vanilla does not have, keyed to
    lock/unlock flags in BioRand's own placement data. Standalone BioRand is safe
    because its item randomizer never relocates key items (CanChangeItem /
    preserve), so keys stay vanilla-placed and match the lock design. Archipelago
    DELIBERATELY shuffles the milestone keys, and its logic (rules.py) models
    VANILLA progression with zero knowledge of these added locks - so an added
    lock whose key AP placed behind it is a softlock (same class as the lodge-key
    bug). Re-enabling requires rules.py to model BioRand's locks first.
